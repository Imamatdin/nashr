## Release procedure

Run `python scripts/release_preflight.py --env-file .env` from the checkout,
or `docker compose exec api python scripts/release_preflight.py` after deployment.
Exit 0 means the five read-only probes pass, not that the entire release is accepted.
The probe cannot verify SQL constraints (including migration 012), RLS correctness,
backups, worker health, model authorization, payments or export fidelity.

Before applying migrations, inspect the migration ledger and schema on the target.
Do not blindly replay 011: it contains an unconditional constraint addition.
Take a backup and follow `docs/RUNBOOK_BACKUP_RESTORE.md` using a separate scratch DB.
Also verify the new documents/revisions tables after restoration.

Build on a host with Docker after the ignore rules land. Inspect the resulting image
for environment files and credentials, and exercise API/worker startup. Old images
may contain secrets if built from a directory containing them; this is unverified.
If confirmed, rebuild and rotate affected credentials through a controlled rollout.

Keep schema migrations additive during rollback; revert application images/routing
without deleting document revisions. Record previous image identifiers before rollout.
